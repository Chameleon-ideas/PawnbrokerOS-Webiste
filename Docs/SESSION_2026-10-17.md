## What changed

### New — `src/components/BookDemo.astro`
Two-column `#book-demo` section placed between `DataProtection` and `FinalCTA`.

- **Left:** eyebrow, serif headline, lede, a three-step "what the demo looks like" list, and three assurance bullets.
- **Right:** sticky card containing `#pawnbrokeros-hubspot-form`, the mount point for the HubSpot embed.
- **HubSpot embed v2** (`js.hsforms.net/forms/embed/v2.js`) is loaded lazily via `IntersectionObserver`
  (600px rootMargin) so the third-party script never competes with the hero render. A `#book-demo`
  hash in the URL forces an immediate load.
- `hbspt.forms.create` is called with `css: ''`, which suppresses HubSpot's own stylesheets — the
  `<style is:global>` block in the component is therefore the single source of truth for the form's
  appearance (fields, select chevron, checkboxes, error messages, submit button, success message).
  Scoped styles cannot be used here because HubSpot injects its DOM after build.
- **Three states once configured:** shimmer skeleton while loading → real form on `onFormReady` →
  fallback card with a `mailto:` link if the script is blocked, errors, or times out (9s).

### Placeholder form — active until the HubSpot IDs are set
Because the HubSpot credentials are not available yet, the component renders a **native placeholder
form** instead (the `hubspotConfigured` branch in `BookDemo.astro`). It is not a mockup:

- Fields: first/last name, work email, shop name, phone, locations select, free-text ask, consent
  checkbox — plus a hidden field carrying the CTA source.
- It deliberately reuses HubSpot's own class names (`.hs-form-field`, `.hs-input`, `.hs-error-msgs`,
  `.hs-button.primary`, `.submitted-message`), so **one stylesheet drives both** the placeholder and
  the real HubSpot form. Swapping in HubSpot changes nothing visually.
- Client-side validation writes into `.hs-error-msgs` so errors look identical to HubSpot's.
- On submit it shows a busy spinner, then opens a prefilled `mailto:` to `PUBLIC_SALES_EMAIL` and
  swaps the form for a success panel — so an enquiry is **not silently dropped** if this ships before
  HubSpot is wired. The success panel also names the address in case the mail client never opened.
- **Self-removing:** the moment `PUBLIC_HUBSPOT_PORTAL_ID` and `PUBLIC_HUBSPOT_FORM_ID` are filled in,
  this branch stops rendering and the HubSpot embed takes over. No code needs deleting.

### New — `src/config/hubspot.ts` + `.env.example`
HubSpot IDs are read from `PUBLIC_HUBSPOT_*` env vars rather than hard-coded. `hubspotConfigured`
gates the embed so an unconfigured build shows the fallback instead of an endless skeleton.
`.env` is already gitignored; `.env.example` documents where each value lives in HubSpot.

> **Status: needs values.** `PUBLIC_HUBSPOT_PORTAL_ID` and `PUBLIC_HUBSPOT_FORM_ID` are empty.
> Until they are filled in, the section renders the placeholder form described below. Nothing is blocked.

### Changed — CTA wiring
Every "Get Started" was previously a dead link. All now point at `#book-demo` and carry a
`data-demo-cta` attribute naming their origin:

| File | Change |
|---|---|
| `Navbar.astro` | `Get Started` → `#book-demo`; added a `Book a Demo` button in the mobile drawer |
| `Hero.astro` | `Get Started`: `#pricing` (broken anchor) → `#book-demo` |
| `FinalCTA.astro` | `Get Started`: `#pricing` (broken anchor) → `#book-demo` |
| `index.astro` | mounted `<BookDemo />` |

A delegated `click` listener on `document` records which CTA was used and writes it into the HubSpot
field named by `PUBLIC_HUBSPOT_PLAN_FIELD` (default `plan_interest`), hiding that field from view.
Delegation is required because `FinalCTA` renders after the BookDemo script in the DOM. If the
property does not exist on the form, the value is silently dropped — nothing breaks.

### Deliberately NOT shown — pricing
**No pricing appears anywhere on the site.** `src/components/Pricing.astro` exists in the repo but is
**not imported into `index.astro`** and does not render — it was already orphaned before this session
and stays that way by explicit decision (2026-10-17): the page should drive visitors to a demo, not to
a price list. Its internal CTAs were repointed from the dead `#contact` to `#book-demo` so the file is
not broken if it is ever mounted, but mounting it is not the intent. There is no `#pricing` anchor on
the page and nothing links to one.
