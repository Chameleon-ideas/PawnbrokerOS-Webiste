### Google Tag Manager added — two containers

**Status: done, verified at runtime. Not committed.**

`src/layouts/Layout.astro` now loads GTM containers **GTM-NJFLPT7C** and **GTM-N7LVCV3K**, high in
`<head>`, with `<noscript>` iframe fallbacks immediately after `<body>`.

The snippet supplied was not usable as pasted and was corrected:

- **Curly quotes** (`“…”`, `‘js’`) would have broken the `src` attribute and thrown a JS syntax
  error. Replaced with ASCII quotes.
- **It mixed GTM with gtag.js.** The paste loaded `gtm.js` (Tag Manager) via a bare `async` tag but
  bootstrapped it with `gtag('js', new Date())`, which belongs to gtag.js. Loading `gtm.js` that way
  skips the `{'gtm.start': …, event: 'gtm.js'}` dataLayer push, so the container initialises but the
  `gtm.js` event never fires and tags on the **All Pages** trigger stay silent. Replaced with
  Google's official GTM snippet for each container.
- **Duplicated block** — the `dataLayer` init and `gtag` definition appeared twice identically. Only
  the container IDs actually differed.

`is:inline` is required on both script tags. Without it Astro bundles them into a deferred
`type="module"` chunk, which delays the container past the initial pageview.

**Verified** against the production build served by `astro preview`: both `gtm.js?id=…` requests
fire, `window.dataLayer` holds 2 `gtm.js` start events, `window.google_tag_manager` is present,
2 noscript iframes render, no page errors, no curly quotes anywhere in `dist/index.html`.
`npm run build` clean.

Not yet checked in GTM itself — confirm both containers report traffic in Tag Assistant once live.
